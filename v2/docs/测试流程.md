# 测试流程

2026-11-24 · QA-001。这份文档说明每项自动检查查什么、什么时候跑。目标是：游玩时才发现的那类问题（贴图和格子对不上、高亮把物品盖住、区块互相压住、缺图、按钮太小、存档读档出错），以后改代码时由检查直接报出来。

## 一条命令

```bash
cd v2
npm run qa          # 类型检查 → 单测（含不变量随机测试、素材引用）→ 行囊贴图 → 死按钮 → 全界面，任一失败就停
```

`npm run qa` 自带开发服务器，不需要先开 `npm run dev`。完整跑一遍约 15–25 分钟，大部分时间在全界面检查。e2e 需要先开开发服务器，单独跑：

```bash
npm run dev                                  # 另一个终端
node tests/e2e.mjs http://localhost:5173/
PORTRAIT=1 node tests/e2e.mjs http://localhost:5173/
```

## 每项查什么

| 检查 | 命令 | 查什么 | 来自哪次 bug |
| --- | --- | --- | --- |
| 类型 | `npx tsc --noEmit` | 类型错误，包括测试文件（vitest 本身不做类型检查） | GAME-007 的测试类型错误 |
| 规则单测 | `npx vitest run` | 每条规则的具体例子（`tests/rules.test.ts`） | 各期玩法 |
| 不变量随机测试 | `npx vitest run tests/invariants.test.ts` | 随机执行拿货、移动、叠放、放回货堆、丢掉、卖、侧袋、道具、委托、战斗、上楼；每一步之后检查：物品不重叠、不出界、不压空洞格；件数在 1 到上限之间；侧袋不超过 3 格；气血不超过上限；石数、灯油合法且没有 NaN；存档读档前后一致。另外同一种子和操作重放两次，结果必须完全相同 | 借鉴 Factorio「重度模式」：每一刻存档、读档、比对 |
| 素材引用 | `npx vitest run tests/assets.test.ts` | 物品图标、怪物立绘和出招图、事件图、法宝图标、卡牌插图都存在；有专属图时只要求专属图，没有时检查替代图 | 传送阵事件缺图（这次查出） |
| 行囊贴图 | `npm run test:bag-art` | 每件物品 × 4 个方向放进真实的行囊界面，读取贴图的实际布局和 CSS 变换，在画布上重画并逐格统计不透明像素：占着的格子几乎没图（空格）、没占的格子被图盖住一大块（溢出）、大半张图画到物品框外，都报错。另外检查配件范围高亮在普通和缝过的行囊里都是半透明 | 竹柄钩占格和贴图对不上；磨刀石周围格子被盖住 |
| 死按钮 | `npm run test:buttons` | 在探索、战斗、狐市、灯台、事件、奖励画面上，从同一状态出发把每个可用按钮各点一次；画面、游戏状态、覆盖层、页面都没变化的记为死按钮（借鉴 PlayGoblin） | 探索时对着墙点「后退」毫无提示（这次查出） |
| 全界面 | `npm run test:screens` | 在桌面 1280×720、竖屏 390×844、魔搭手机页 390×664 下打开每个画面（标题、帮助、成就、图鉴每条、镇灯铺每张委托和兵器、探索、行囊、牌组、每只妖的战斗、每个事件及结果、狐市、灯台、宝箱、奖励、结局），报告：文字超出所在框、文字被裁掉、按钮点不到、不同元素的文字叠在一起、手机上按钮小于 24×24 像素 | UI-004 文字超框；UI-006 镇灯铺区块互相压住；QA-001 触控尺寸 |
| 模拟平衡 | `REPORT=1 SEEDS=200 npx vitest run tests/report.test.ts` | 胜率、每只妖的掉血和致死率、每层收支、装不下留下的货、行囊占用 | GAME-004 |
| 套装价值 | `REPORT=1 SEEDS=300 npx vitest run tests/sets.test.ts` | 每档套装带来的胜率和库银 | GAME-006 |
| e2e | `node tests/e2e.mjs`（加 `PORTRAIT=1` 为竖屏） | 从标题打到结局的完整流程，含学牌的二次确认 | 各期界面 |
| 叫声 | `node tests/hearing-check.mjs` | 妖叫声看得见、绕拐角、隔墙三种情况的响度和亮度 | AUDIO-002 |

## 什么时候跑

| 改了什么 | 至少跑 |
| --- | --- |
| 玩法、数值、背包规则 | 类型、单测（含不变量）；改数值时加模拟平衡 |
| 物品数据（形状、倾斜、图标） | 加行囊贴图、素材引用 |
| 界面、样式、文案 | 加全界面；改流程时加 e2e |
| 素材文件 | 素材引用、行囊贴图 |
| 提交前 | `npm run qa`，加 e2e 两种尺寸 |

## 失败了怎么看

- **不变量**：失败信息形如「seed 11, step 2 (add abacus): abacus stack of 2 (max 1)」，用同一个种子能重放到出错那一步。`FUZZ_SEEDS=400 FUZZ_STEPS=400` 可以加大规模。
- **行囊贴图**：形如「[empty] hook rot 0: occupied cell 0,0 is 0% covered」。先看物品的 `shape` 和 `tilt` 是否和图一致；细长的图（照影剑、墨壳）端头本来覆盖少，门槛是 3%。
- **全界面**：截图存在 `.cache/overflow/`，文件名是「尺寸-序号」，和输出里的序号对应。

## 写新检查的原则

- 界面类检查（全界面、行囊贴图）在页面里把动画和过渡时长设为 0 再测，测的是画面定下来以后的样子。

- 只写确定性的检查：固定种子、固定画面，同样的代码每次结果一样。
- 失败信息要能直接定位：哪个物品、哪个方向、哪一格、哪个画面。
- 新检查合进来之前，先故意埋一个对应的错误，确认它会失败。QA-001 的不变量测试用「叠放不检查上限」验证过。
