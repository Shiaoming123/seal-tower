# 塔里两位狐老板娘，有一位是假的｜《斩妖塔 · 富婆狐商救救我！》创作手记

- **作品名称：** 斩妖塔 · 富婆狐商救救我！

## 1. 创意与玩法

### 先认识一下绯绡

她是这座塔里唯一肯收妖货的狐老板娘。红衣，三条尾巴，说话爱眨眼。你从妖身上剥下来的灯灰、狐扣、钟铜，她都收，只是压价，比带回镇上少两三成，同一种货收多了还越收越便宜。

到了第二层桥驿，你可能会撞见另一个狐市。摊主也是狐女，也冲你笑，货便宜得出奇，只是尾巴是白的。游戏里的原话是：

> 又一个狐市？摊主也是个狐女，可尾巴是白的，货价便宜得出奇。绯绡说过，塔里只有她一家狐市。

你可以买她的便宜货（有一半可能是一把树叶），也可以一刀挑开摊布。底下是九条白尾巴，它不笑了。它出招「收账」，打穿你的格挡就抢走 12 石。

【图：`docs/contest/media/cover-fakefox.jpg`】

### 这到底是个什么游戏

塔里的妖偷光了镇上的灯油。你是给镇灯铺供货的斩妖人：接一张委托，带一件兵器进塔，把货活着背回来。

一趟分四件事：

1. **走。** 第一人称走三层随机迷宫：照影廊、桥驿、钟楼。每走一步烧一点灯油，灯灭了小地图不再探路，妖每下多打 3 点。不必每间屋子都进。
2. **打。** 卡牌战斗，每回合 3 点能量、抽 5 张。妖头上明写下一手要做什么：灯鼠打穿格挡会叼走你最值钱的货，蓄力的妖打够伤害就能打断，狐妖颈下的狐扣挨一记重击就碎。每只妖都有自己的「取材条件」，想带回完整的材料，就得换一种打法。
3. **装。** 行囊就是构筑。剑占 1×3，算盘占 2×2，钩子是 L 形。兵器放进行囊，它的牌才进牌组；卖掉，牌就没了。磨刀石夹在两把剑中间，两把剑的攻击牌都 +2；刃、盾、灯、钱、妖材凑够件数有套装效果；剑挨着磨刀石打完一仗会淬成「精」品；扩囊衬布能把新格子缝到行囊任意一边；狐扣、水珠、钟铜这些易碎货挨打会掉成色、掉价；侧袋里的东西不生效，但不会被抢。
4. **卖还是背回家。** 卖给绯绡换药、换刀、买灯油，还是背着上楼、活着回镇折成库银？库银用来营建镇灯铺（账房、灯油坊、药柜、行囊匠……），让以后每一趟开局更强。倒在塔里，背上的全丢。

每层开局抽一支签（雨夜、集市日、妖潮、灯会、血月……共 10 种），改变这一层的规则。三层各有守关妖，前两层各从两只里随机一只，最上面固定是背着铜钟的负钟君。四位委托人（灯匠、绯绡、药铺、镇长）各要各的货，交情越深单子越大，他们的身世随交情一点点揭开。

内容量：19 种妖（含精英和守关），15 个事件，约 50 张牌，18 件装备，20 多种货物，13 件法宝，8 座可营建的铺面。

### 亮点

- **一件货有三种用处。** 卖钱、交委托、或者被某些牌烧掉换伤害（引灯盘流）。什么时候卖、卖给谁、背不背上楼，是每一层都要重新算的账。
- **你想带回什么，决定了这一剑怎么出。** 取材条件把「打赢」变成「怎么赢」。
- **声音全部是代码合成的。** 古琴、琵琶、古筝用物理建模合成，竹笛带气声和颤音，还有大鼓、梆子、寺钟和每层不同的混响。没有一个外部音频文件。

### AI 和我各做了什么

| 谁 | 做了什么 |

| **Codex（OpenAI）** | 美术：用内置图像生成画角色、妖怪（含出招、受击姿态）、事件插图、委托人立绘、卡牌插画、法宝图标和宣传主视觉；搭好母图 → WebP 的导入管线和美术清单；组织独立画审；维护协作规范、开发导航和素材追溯检查 |

两个 AI 在同一个 Git 仓库里干活，靠一张公开的任务清单协作：开工先认领任务、写清楚要动哪些文件，做完写开发日志、跑检查、rebase 后推送。美术文件只有 Codex 改，规则代码只有 Claude 改，碰到对方的范围就在清单里写交接。

一个例子：行囊重设计的初稿要给 7 件新配件画图（有方向的束带、八卦镜、灯笼……）。参赛者说「一味堆砌美术会造成大量的浪费，接下来对于美术的需求需要有根据的提出了」。Claude 把方案改成「淬炼」：装备挨着指定配件打完一仗就升级为精品，沿用原图加一个金色角标。7 张新图一张都不用画。

## 3. 工具应用与体验

- **Claude（Anthropic，Claude Code）：** 写代码、调试、写测试和模拟、调参、写文档，也用 Playwright 驱动本机 Chrome 自己试玩、截图、录音频、检查响度。体验上最省事的是「改完自己验」：每次改完跑 81 项单测、几百局机器人整局模拟和浏览器端到端试玩，再提交。
- **Codex（OpenAI）：** 内置图像生成（ImageGen）出透明底 PNG 母图，v2 这一轮新导出了 137 张：妖怪和动作、事件、委托人立绘、49 张卡牌插画、13 个法宝图标（另有主角、绯绡、道友和部分场景沿用前几轮同样方式生成的图）。三张宣传主视觉先出两三个构图草稿，挑定再出终稿；用待机图作参考生成出招、受击姿态，保证同一只妖前后一致。每批图有独立画审，查手指、透明边、动作衔接和在游戏里的实际大小，退回重画过好几次（比如白狐的手）。
- **Qoder：** 没有使用。
- **魔搭 API Inference：** 没有使用。游戏运行时不调用任何模型，打开网页就能离线玩。
- **赞奇科技 / 华硕 DGX Spark 节点：** 没有使用。
- **其他：** Vite + TypeScript + Preact 搭网页；Vitest 跑规则单测和整局模拟；Playwright + 系统 Chrome 做端到端试玩、创空间嵌入验收和演示视频录制；sharp 压图；subset-font 按游戏实际用字裁剪字体。

## 4. 问题与解决

### 守关妖的倍率，从来没生效过

**现象。** 数值体检时，第一层守关灯蛾娘平均只让玩家掉 2.4 点血，目标是 8–14。看起来是「守关太弱」，第一反应是把它的血和伤害往上调。

**真正的原因。** 每层的怪物表 `FLOOR_SPAWNS` 里给守关妖写了血量倍率和伤害加成，但生成迷宫的 `dungeon.ts` 在放守关妖时没把这两个数带上。也就是说，之前所有关于守关难度的调整都是改了个寂寞：数字写在表里，游戏从来没读。

**怎么发现的。** 这个 bug 能藏这么久，是因为之前的平衡模拟只看「每把兵器的总胜率」。胜率看着合理，就没人去看单只妖。GAME-004 先把模拟报告做细：每只妖按「层 + 类型」分开统计遭遇数、击杀回合、造成的掉血、致死次数。守关数字明显偏离，再顺着代码查到生成环节。

**改进。** 生成守关时带上倍率，加了一项单测锁住「守关带上本层倍率」。修完后两只第一层守关的平均掉血是 7.8 和 8.8，进了目标区间。

### 模拟的机器人从来不卖货

同一次体检还发现：模拟用的机器人从不卖货、不买法宝，可「跑商」是这个游戏的主线。补上「按简单规则卖货」以后，随手打的胜率从 21–27% 跳到 50–63%：之前以为偏难，其实偏简单。调参后四把兵器的胜率在 43–47%，彼此相差 4 个百分点，死因不再集中在一只妖身上。

| 机器人 | 照影剑 | 木挡板 | 引灯盘 | 算盘 |
| --- | --- | --- | --- | --- |
| 不卖货、不买法宝 | 21% | 27% | 23% | 26% |
| 会卖货（调参前） | 63% | 50% | 63% | 61% |
| 会卖货（调参后） | 44% | 45% | 47% | 43% |

### 测音频，测进了另一套音频引擎

录音效试听时，每段底下都有一层若有若无的镇上配乐。原因是测试脚本用 `import("/src/audio/sfx.ts")` 拿音频模块，而开发服务器改过文件后会给页面里的模块加 `?t=…`，测试拿到的是第二份模块、第二个 AudioContext，游戏自己的配乐一直在底下响着。改成从页面已经加载的资源里找到同一个模块地址再导入，开测前先停掉游戏的声音、先测一次静音底噪（从 0.013 降到 0），之前的试听片段全部重录。

### 自动检查抓到了真人会卡住的按钮

用户发来一张截图：兵器卡最后一行字掉出了卡片。Claude 没有只修这一处，而是写了一个检查脚本：把每个画面（每只妖的战斗、每个事件、图鉴每一条、老玩家才能解锁的内容）在横屏、竖屏、矮屏手机三种尺寸下都打开一遍，找出文字超出框、被裁掉，或者按钮跑到屏幕外点不到的地方。

结果找出 10 处，有几处比截图里那处严重得多：

- 点第一张牌后整个画面上移 28 像素，顶栏被切。舞台虽然设了 `overflow: hidden`，仍会被浏览器滚动，焦点落到伸出屏幕的手牌上时就滚了。改成 `overflow: clip`。
- 手机上打开牌组浮层，关闭按钮跑到屏幕上方 289 像素外。手机没有 Esc 键，打开就关不掉。
- 行囊装满时，事件结果页的「继续」按钮掉到屏幕外；打通三层后，结算页的「再进一趟」也是。这两处是创空间验收的机器人卡住后才发现的，真人玩家碰上就只能刷新页面。

修完之后，三种尺寸都是 0 处，这个检查也留在仓库里，每次打包前都跑。

## 5. 经验总结

- **让 AI 自己验，比让它多写重要。** 每个改动都配一条能自动跑的检查：单测、整局模拟、浏览器试玩、嵌入验收。AI 写错不可怕，怕的是没人发现。
- **报告要细到能看见单个东西。** 总胜率掩盖了守关倍率失效、机器人不卖货两个大问题。拆到「每只妖、每层收支」才看出来。
- **两个 AI 分工，靠的是一张写清楚边界的任务清单。** 谁改哪些文件、怎么交接、什么算做完，写下来就不会互相踩。
- **「美术要有根据」是好约束。** 先想能不能用现有的图把玩法做出来，再提新图需求，省下的时间花在手感、数值和测试上。

**接下来想做的：** 找真人试玩，看大家能不能说清「现在卖还是背上楼」的取舍、第二局会不会主动换路线；把第一层的教学做得更自然；手机真机上再调一轮触控手感。
