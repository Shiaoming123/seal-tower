## 为什么

用户截图：书虱的身体伸进两侧墙里，整张图很糊。

## 原因

- **卡墙**：立绘按图片宽高比画。书虱这种长身体的图，画出来比走廊还宽，伸出去的部分画在了侧墙上。
- **模糊**：整个 3D 画面在 384×216 的画布上渲染再放大。墙面本来就是像素风没关系，但高清的怪物立绘被缩到一百来像素高再放大，就糊了。

## 做了什么

- 立绘逐列绘制时，算出这一列在怪物所在深度对应的世界格子；落在墙格里（且不是怪物自己那格）就不画。长身体到墙角就被墙挡住。
- 墙面、地板、天空仍在 384×216 上计算，用最近邻放大到 2 倍画布，保留像素块；怪物立绘、影子、光晕直接画在 2 倍画布上，开高质量平滑。
- 3D 画布的 CSS 从 `pixelated` 改为 `auto`：墙面的像素块已经在画布里放大好了，显示时平滑缩放只影响立绘边缘。
- 逻辑坐标（`VIEW_W`、`VIEW_H`）不变，战斗取景等换算不受影响。

## 验证

- 书虱放在直走廊前方两格：身体在走廊内，尾巴到右侧墙边被挡住。[走廊](assets/UI-010-corridor-after.jpg)
- 进入战斗：书虱的鳞片和触须清晰可见。[战斗](assets/UI-010-combat-after.jpg)
- 完整检查和 UI-009 一起跑。

## 限制

- 怪物被墙挡住的判断按格子算，转身动画的中间帧里可能有一两列误差。
- 2 倍画布的绘制量在手机上没有实测帧率。墙面计算量不变，只多了立绘的列数。
