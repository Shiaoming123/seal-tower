## 为什么

第六次上传时，`npm run qa` 里的全界面检查（`overflow-check`）一轮要十几分钟，像卡死。用户要求修掉。

## 查到的原因

用 Playwright 跟踪（`DEBUG=pw:api`）统计每次点击的耗时：

1. **选牌遮罩不清除。** 检查依次打开每个事件，再用 `reset()` 把画面拨回探索。但 `reset()` 不清 `run.cardPick`：某个事件一旦打开「升级 / 删除 / 复制一张牌」的选牌框，这个框就一直盖在后面所有事件、狐市、灯台、宝箱上。那些点击全打在遮罩上（Playwright 报 `.overlay … intercepts pointer events`），每次等满 3 秒超时。
2. **竖屏点不到第一张手牌。** 奖励那一仗每回合点 5 次「第一张能打的牌」。竖屏手牌是扇形，第一张的中心被第二张盖住，又是每次 3 秒，8 个回合约 120 秒。这和之前创空间验收 bot 遇到的是同一个问题。

## 改了什么

- `v2/tests/overflow-check.mjs`
  - `reset()` 顺带清掉 `run.cardPick` 和弹层；
  - 奖励战改打最后一张牌（它完全在最上层），两步出牌的布局再点一次选中的牌；已经不在战斗里就停。
- 遮罩一清，狐市第一次真正被检查到，查出一处**真问题**：照影剑的说明（「牌：合锋、连斩　每回合第一张攻击牌伤害 +2。」）在 108×150 的货格里被裁掉 10～14 像素，三种尺寸都有。`v2/src/styles/main.css`：`.item-ware` 改成最小高度 150 像素、说明不再 `overflow: hidden`，长说明把货格撑高，同一行的货格一起变高（flex 默认拉伸），狐市中栏本来就能滚动。

## 验证

- 全界面检查：桌面、竖屏、手机矮屏都是 0 个问题、0 个报错；用时从十几分钟降到约 4 分钟（桌面约 1.5 分钟，没有一次等待超过 1.5 秒）。
- 临时打印确认：三种尺寸的奖励战都真的打到了奖励页，奖励页照常被检查。
- `npm run qa` 全部通过（见下方提交说明）。
