## 结论

竖屏手机上 7 张手牌叠得太紧，只看得全最右一张，其他牌的插图和说明都被盖住，点一下又会直接打出。用户要求一起改掉。现在：

- **竖屏或没有悬停的触屏设备**：第一下点牌只「选中」，那张牌抬高、放大（竖屏 1.55 倍）、摆正、浮到最上层，上方显示「再点一下打出」；再点同一张才打出。点另一张就换选中，点手牌以外的地方取消。
- **桌面鼠标**：不变，单击直接打出，悬停抬起放大。数字键 1–9 照旧直接出牌。
- 悬停抬起只在有真悬停的设备上生效（`@media (hover: hover)`），免得手机上点过后一直停在抬起状态。

## 做了什么

| 文件 | 改动 |

| `v2/src/ui/Combat.tsx` | `picked` 状态记选中牌的 `uid`（出牌后编号变化，选中自动作废）；`twoStep()` 判定：舞台是竖屏，或 `matchMedia("(hover: none)")`；战斗根节点 `onPointerDown` 点在手牌外时取消选中 |

| `v2/tests/studio-check.mjs`、`v2/tests/e2e.mjs` | 触屏／竖屏点牌后若只是选中，再点一下 |

## 限制

- 没在真机上试手感，判定靠竖屏舞台或 `hover: none`。平板横屏且没有鼠标时也会走两步出牌。
- 选中的牌靠左时会贴近屏幕左边缘（最左一张放大后左边距约 5 px），没有被裁掉。

## 第二轮（同日晚上）

- **选中的牌被新手提示盖住。** 手牌容器 `.hand` 自成层叠上下文（z-index 5），战斗里的「知道了」提示是 6，所以牌放大后还在提示底下。选中时把整个手牌区抬到 30：`.hand:has(.hand-slot.picked) { z-index: 30; }`。
- **验收脚本：** 出牌前先点掉「知道了」提示；桌面和手机两项在第一层楼梯口选「回镇结算」（顺带测回镇结算页），并且和爬塔项一样揭开地图。原因：这两项原本只在死亡或通关时结束，机器人活得久就超过 12 分钟时限；抽到「迷雾」签时它只会往看过的格子走，一直撞墙。这些都只是让机器人能走完，不影响检查的内容（包能不能完整跑一局、重开、续玩）。
