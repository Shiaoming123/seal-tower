## 为什么

用户：「视觉动效和交互上面的丝滑感和流畅感需要很多功夫钻研一下，这块我在实际游玩中感觉是游戏反馈感很重要的一环。」

改之前：画面切换只有 0.32 秒的淡入；行囊、牌组、暂停这些覆盖层直接蹦出来；按钮悬停只变亮；行囊物品放下时瞬移；顶栏石数、血条直接跳变。

## 做了什么

统一一套缓动：落定用快出慢停（`--ease-out`），弹出用轻微回弹（`--ease-pop`）。

| 地方 | 改动 |
| --- | --- |
| 按钮 | 悬停上浮 1 像素，主按钮加暖色光晕；按下缩到 97% 再回弹（0.05 秒）；键盘操作时有金色焦点框 |
| 选项、委托卡、兵器卡、商品、法宝选择 | 悬停上浮 2 像素、微亮；按下轻压 |
| 覆盖层（行囊、牌组、暂停） | 背景 0.18 秒渐暗，面板从 95% 带回弹放大进场 |
| 画面进场 | 事件：立绘轻微缩放淡入，文字框上滑，选项依次出现。狐市：货架三排依次上滑，卖货面板从右滑入。镇灯铺：委托卡、兵器卡依次出现。结算页：托盘和右侧依次上滑。结局框上滑 |
| 行囊 | 物品换位置时 0.14 秒滑过去（放下、自动整理、缝补时被挤开）；选中的物品微微放大；拖动时的影子带回弹出现；叠放数量「×N」有描边，压在图上也清楚 |
| 数字 | 顶栏石数滚动到新值，增加时变金并微微放大，减少时变红；血条（玩家和敌人）掉血时红光加小抖动，回血时绿光 |
| 减少动态效果 | 系统开启时关掉上述进场、悬停和滑动，伤害浮字、横幅这类带信息的动画保留 |

数字滚动用 `requestAnimationFrame`，另有定时兜底：帧被节流（后台标签页）时，到时间直接落到最终值，不会停在旧数上。

## 验证

| 检查 | 结果 |
| --- | --- |
| 浏览器 | 石数 60 → 85 滚动并落定；行囊覆盖层的面板动画为 `box-in`；行囊物品的过渡属性是 left、top、opacity、transform |
| 完整检查 | `npx tsc --noEmit`、87 项单测；全界面检查桌面、390×844、390×664 都是 0 个问题；桌面和竖屏 e2e 无页面报错 |

预览窗格里 `requestAnimationFrame` 不出帧，所以数字滚动的中间过程是靠定时兜底验证的，真实浏览器里的逐帧效果没有录屏。
