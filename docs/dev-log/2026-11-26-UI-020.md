## 为什么

第二轮 AI 试玩（REVIEW-003 第 3 条，当时暂缓）量过，390 宽手机上竖屏的实际字号：

- 牌面正文约 9.7px，牌类型标签约 7.9px；
- 敌人血量、牌堆数约 9.4px。

原因是竖屏用 540 宽的舞台整体缩放到手机宽度，系数是 0.72。

## 改了什么

- **竖屏舞台 540 → 480 宽。** 390 宽手机上缩放从 0.72 变成 0.81，所有字和按钮同比放大约 12.5%：牌面正文约 11px，顶栏按钮约 31px 高。舞台高度照旧跟着屏幕比例走。
- **竖屏牌类型标签 11 → 12.5px**（舞台像素），手机上约 10px。
- **竖屏手牌扇形再收紧**（每张 5.6 → 6.1px），8 张也不出屏。
- **竖屏探索画面适配 480 宽。** 原来 `1fr` 的列会被最宽的子元素撑开（小地图加「前面」、四个 120px 的走路按钮），整屏超出舞台。改为 `minmax(0, 1fr)`；走路按钮平分一行；小地图 250px、图例折两行，让「前面」放在小地图旁边；提示框不超过画面宽度。
- **竖屏图鉴标题换行。** 分类标签单独一行，「0/21」不再被挤出屏外，「图鉴」不再竖排。
- **新增 `edge-sweep-check`。** `overflow-check` 把所有「被舞台边裁掉」的问题记成同一条，只显示第一处，这次探索画面整屏超出时它只报了指南针。新检查在竖屏 390、360 宽下，逐个列出主要画面里超出舞台边的元素。
- **修了 `hand-fit-check` 的判定。** UI-019 让底部玩家面板不接收点击（`pointer-events: none`），原来按点击命中判断「伤害预告是否被手牌盖住」会误报。改成按几何重叠和层级判断。
