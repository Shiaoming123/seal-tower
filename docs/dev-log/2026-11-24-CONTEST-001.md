## 创空间嵌入验收

`node v2/tests/studio-check.mjs`：用本地服务器把包放在子路径下（模拟创空间网址），宿主页放在另一个域名，用 iframe 嵌入（localhost 对 127.0.0.1，属于跨站），每次都是全新的浏览器配置。

| 检查 | 桌面 1280×720 | 手机 390×844 触屏 | 三层爬塔 |
| --- | --- | --- | --- |
| 标题页出现 | 363 ms | 409 ms | 138 ms |
| 两套字体加载 | ✓ | ✓ | ✓ |
| 声音：关掉后存进 iframe 存储，再打开 | ✓ | ✓ | ✓ |
| 屏幕按钮「左转 / 前进」能移动（手机用 tap） | ✓ | ✓ | ✓ |
| 打一整局到结束 | 第一层阵亡，15 步 | 第三层阵亡，84 步 | 击败负钟君登顶，75 步，2.4 分钟 |
| 「再进一趟」重开、刷新后出现「继续上一趟」 | ✓ | ✓ | ✓ |
| 页面报错、4xx/5xx、外部请求 | 0 | 0 | 0 |

测的是改名后的包（`dist-studio.zip` 哈希见下）。随机两局里，灯灭时会给机器人补满灯油：灯灭后点小地图不再自动走、迷宫也不再往外探，这个简单的机器人会困在黑暗里。真人会找狐市、灯台添油。

**三层爬塔**是为了确认第二、三层和各守关的图和音乐都能从包里加载。机器人只会打出第一张能出的牌，正常打在第一层就会死，所以这一遍每次探索时补满气血和灯油（灯灭后点小地图不会自动走）、揭开整张地图（迷雾签会藏住守关妖），进战斗时把妖的血压到 1；先奔守关和楼梯，被挡住就先清最近的挡路者。它不代表难度。调这一遍时先后撞上灯油耗尽、迷雾、挡路、打赢后没点进结算页、「进塔」按钮误匹配到写着「带 32 石进塔」的算盘卡、反复逛同一家狐市六个问题，都是测试脚本的问题，不是游戏的，已全部在脚本里解决。结果见 [验收报告](../contest/media/studio-check/report.json)。

## 演示视频怎么录的

`node v2/tests/record-demo.mjs [输出.mp4]` 会自己起 Vite 开发服务器，用系统 Chrome（headless）打开一个宿主页：游戏放在同源 iframe 里，字幕层盖在上面。

- 开发入口（`__seal.fight` / `__seal.event`）按顺序打开狐市、灯鼠战斗和白狐摊，并往行囊里塞一枚完整狐扣和两份灯灰用来卖。所以视频是**按脚本走一遍真实界面**，不是随机一局。
- 分段：封面 0–4 秒 → 绯绡的狐市 → 第一人称迷宫（15 秒起）→ 灯鼠战斗（26 秒起）→ 行囊（42 秒起）→ 可疑的白狐摊和假狐商（52 秒起）→ 回镇结算和营建铺子（69 秒起）→ 片尾（79 秒起）。

录制时踩的三个坑，都已在脚本里解决：

1. **默认 H.264 档位装不下 1080p，文件解不开。** 改为指定 `avc1.640028`（High，4.0 级）。
2. **头几帧是 1280×720，之后才变成 1920×1080。** MP4 只按第一帧记录编码参数，中途变尺寸整段就解不开（macOS 和 Chrome 都报解码错误）。现在开录前用隐藏的 video 元素预览，等尺寸稳定再开录。
3. **headless Chrome 录到的标签页声音是静音。** 改为把游戏 Web Audio 里所有接到扬声器的连接复制一份进 MediaStream 单独录 AAC，最后用 AVFoundation（`mux-av.swift`）把两路无损合成一个 MP4，并把元数据放到文件开头。

成片：82.6 秒，1920×1080，H.264 + AAC 立体声，约 33 MB。每 4 秒抽一帧，21 帧全部能解码；每 10 秒的 RMS 在 0.015–0.038 之间，峰值不超过 0.30，全程有声音、不破音。
