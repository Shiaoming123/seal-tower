## 3. 查项目资料的关系

| 起点 | 关系 | 下一步 |
| --- | --- | --- |
| 任务 | 涉及实体、依赖任务、产出素材与日志 | 以 [协作任务](协作任务.md) 的 ID 串起分工和验收，跟随对应日志 |
| 实体 | 使用素材或程序表现 | 从游戏数据找稳定 ID。动作如 `bell-heavy-attack` 属于实体 `enemy:bell` 的二阶段 |
| 素材 | 来自母图，导出为运行图 | 从 [导出记录](../v2/art/exports.json) 按 ID 找母图与 WebP 哈希；[美术清单](../v2/docs/美术清单.json) 记录现状和待补图 |
| 证据 | 验证任务、实体、素材在某版本的表现 | 日志链接独立评审，逐项注明版本、输入、视口与结果 |
| 文档 | 补充或替代另一份文档 | 新的设计和记录注明承接来源，并链接原文与更细的场景、实现或证据 |

[资料索引](资料索引.json) 定义归属，命令 `cd v2 && npm run docs:check` 会枚举仓库资料，检查漏归类和已登记的任务关系。检查本次新增日志时带上 `-- --base origin/main`。填写要求见 [协作规范](Agent协作规范.md)。

- [字体与许可](../first-cut/type/README.md) · [旧版占格规范](../first-cut/行囊物件入库规范.md) · [对话参考截图](conversation/screenshots/README.md)。
- 参赛阶段资料可按 [技术调研](../赛前技术调研.md) · [参赛与开发计划](../参赛与开发计划.md) · [构想帖草稿](../报名构想帖-草稿.md) · [创作手记](../创作手记-工作底稿.md) 查阅。
