# 旧原型接手说明

这里记录 `first-cut/` 的试玩和开发步骤。当前开发按 [v2 运行说明](../v2/README.md) 执行，文档与素材先查 [开发导航](开发导航.md)。

## 入口与代码地图

| 范围 | 代码 |
| --- | --- |
| 最早斩妖塔原型 | 根目录的 index.html、game.js、arena.js、art.js、screen.js、sound.js 和 tower-art.js |
| 照影廊第一剑、一印两价、物品与押运 | first-cut/index.html、cut.js、bazaar.js、market-play.js、bag-ui.js、escort-ui.js |
| 镇灯铺共用供货规则与界面 | first-cut/hunt-rules.js、hunt-ui.js、hunt-scene.js、hunt-art.js |
| 第一人称格图、卡牌与画面 | first-cut/crawl-world.js、crawl-cards.js、crawl-scene.js、crawl.css |
| 离线打包与字体 | first-cut/build_offline.py、first-cut/type/、sprite-bank.js、font-bank.js |

在仓库根启动本地静态服后，使用 `/first-cut/?play=crawl&seed=1`。开新隐身窗口能拿到新签内状态。当前签的进行中状态在 sessionStorage，跨局的委托信誉在 localStorage，两者按页面路径区分。离线版与 HTTP 版、不同使用机器或浏览器的存档各自独立。若需迁移个人存档，使用者应另行选择导出方式。

从标题选择「镇灯铺 · 入塔接单」。要验证第二层签 1 的扣价与护筐，接「替绯绡取扣」，带木挡板时留意「架招」能挡满 5；到桥驿对照报价，出门到旧灯台，收灰后走两格到岔口，左转，沿鼠洞走两格。入战后守住第一个掀筐，再在战后货托用灰手动换扣。灰单用同签也可比较 3 灰价格或东侧找灰。观察旧版与新版时使用独立浏览器上下文。

## 一次迭代怎么验

1. 先跑 `npm test`。遇到背包字形或浏览器交互变化，再跑 README 所列字库或浏览器命令。
2. 构建前用各自的本地回放目录和候选输出，确认无意影响固定机位、第一人称路线和签内状态。可用 `python first-cut/build_offline.py --verify-inventory dist/verify --output dist/seal-tower.html` 跑包括像素占格在内的成套检查。
3. 玩法有变化时，记录同签、初见报价时的选择、第一张变更的牌和最终账本。画面有变化时，保留桌面与 390 宽触控模拟的同机位对照，区分连续镜头与静态截图。
4. 新包确认首轮伤害、满包或退场、实际成交和刷新路径。用户反馈过的阻断包括锁按钮无下一步、点击画面误触选择、长按释手出牌、页面在换选择时跳动。

最新基准包日期是 2026-11-23 的接手快照，来自此前本机的「桥驿入洞」构建，游戏 HTML SHA-256 为 `0207cf2e806e59aa4f6c502b95b99341ba04f867c28ab26b9556ba5f6fa53ee4`。仓库初次建库自当前状态开始，之前的时期用历史证据串起来。
